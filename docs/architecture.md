# Geo Guessing Platform Architecture

## Architecture decisions

- The monorepo is split by runtime boundary: `apps/web` for Next.js, `apps/api` for Hono and Socket.IO, `packages/db` for Drizzle, and `packages/shared` for zod-backed contracts.
- Shared contracts are the source of truth for HTTP payloads, websocket events, game modes, room state, and validation. UI code should consume types from `@workspace/shared` instead of redefining shapes.
- Persistent state lives in PostgreSQL through Drizzle. Redis is reserved for transient multiplayer state: room presence, timers, reconnect windows, and synchronized match state.
- Better Auth is mounted inside the Hono API so auth, REST routes, and websocket session checks share one server boundary.
- The web app uses Server Components by default. Client-only code is limited to providers, Socket.IO helpers, TanStack Query hooks, and ephemeral Zustand game state.
- mapcn should be installed as owned shadcn-style map components in `apps/web/components/ui` when map gameplay is implemented. It is not treated as another component library dependency.

## Shared types architecture

- `validators` contains zod schemas for primitive payloads and route inputs.
- `contracts` contains API response and domain DTO schemas.
- `events` contains typed Socket.IO event maps and runtime schemas.
- `constants` contains gameplay limits such as round counts, timers, and room constraints.
- `types` contains stable domain unions shared by frontend, backend, and persistence mapping.

## DB schema plan

- Auth: `users`, `sessions`, `auth_accounts`, `auth_verifications`.
- Game content: `quiz_questions`, `map_locations`.
- Match persistence: `matches`, `match_players`.
- Multiplayer rooms: `rooms`, `room_players`.
- Rankings: `leaderboard_entries`.
- Migrations are generated by Drizzle from `packages/db/src/schema/index.ts` into `packages/db/src/migrations`.

## Websocket event plan

- Client events: `room:join`, `room:leave`, `room:ready`, `match:start`, `quiz:answer`, `map:guess`.
- Server events: `lobby:state`, `match:started`, `match:timer`, `scoreboard:update`, `player:disconnected`, `player:reconnected`, `error`.
- Every event payload is validated through the zod schemas in `@workspace/shared/events`.

## Implementation roadmap

1. Foundation: package manifests, shared contracts, Drizzle schema, env validation, Hono server, Better Auth, Redis, Socket.IO.
2. Auth UX: Better Auth client wiring, Google login/logout flows, protected dashboard data loading. Next.js 16 route protection lives in `proxy.ts`, the renamed middleware convention.
3. Room lifecycle: create/join APIs, lobby UI, ready states, owner transfer, disconnect/reconnect recovery.
4. Match engine: quiz and map scoring services, PostgreSQL match records, Redis live match state.
5. Gameplay UI: quiz screen, mapcn map picker, Google Street View embed, timers, scoreboard.
6. Production hardening: rate limits, observability, migration CI, seed data, E2E tests.
